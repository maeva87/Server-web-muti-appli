Le projet

L'objectif est de montrer qu'il est possible d'héberger plusieurs applications développées dans des technologies différentes sur un même serveur, accessibles chacune via leur propre sous-domaine en HTTPS.

🌐

Sous-domaines distincts

Chaque application est accessible via son propre sous-domaine. Nginx redirige le trafic vers le bon conteneur.

🔒

HTTPS partout

Chaque sous-domaine dispose d'un certificat TLS. Les connexions HTTP sont automatiquement redirigées vers HTTPS.

📦

Conteneurs isolés

Chaque application tourne dans son propre conteneur Docker. Les dépendances sont isolées et le déploiement est reproductible.

Les deux sites

static.localhost

Site vitrine TechCorp

Site HTML/CSS statique présentant l'entreprise TechCorp. Servi directement par Nginx sans passer par un runtime.

  • HTML, CSS, JavaScript vanilla
  • Servi par Nginx (fichiers statiques)
  • Navigation SPA côté client
  • Formulaire de contact
node.localhost

Application Node.js

Application Express.js présentant l'infrastructure du projet. Nginx fait office de reverse proxy vers le port 3000.

  • Node.js + Express
  • Proxifié par Nginx
  • Conteneur Docker dédié
  • Ce site que vous lisez

Stack technique

Docker & Docker Compose
Conteneurisation de chaque application. Le docker-compose.yml orchestre l'ensemble des services.
Nginx
Reverse proxy qui reçoit toutes les requêtes entrantes et les redirige selon le sous-domaine demandé. Gère aussi la terminaison TLS.
Certificats TLS
Certificats auto-signés générés pour chaque sous-domaine. En production, Let's Encrypt peut être utilisé à la place.
Node.js + Express
Runtime JavaScript côté serveur. Express gère le routage HTTP et sert les fichiers statiques de cette application.
HTML / CSS / JS
Le site vitrine est entièrement statique. Aucun runtime nécessaire, Nginx le sert directement depuis le système de fichiers.
